# 02: Entry 작성과 목록 조회

**What to build:** 누구나 Author name, Message, Entry password를 입력해 Entry를 남길 수 있습니다. 누구나 전체 Entry 목록을 최신 작성순으로 볼 수 있습니다. 요구사항의 **작성(Create)**과 **조회(Read)**에 해당하고, 스키마부터 Guestbook 모듈, Neon 저장소, Server Action, UI까지 전 계층을 처음으로 관통하는 티켓입니다. 이후 수정·삭제가 쓸 비밀번호 해시도 여기서 만듭니다. 세부 규칙은 스펙(`.scratch/guestbook/spec.md`)의 검증 규칙, 비밀번호, 표시 절을 따릅니다.

**Blocked by:** 01 (방명록 뼈대와 개발자 표시)

**Status:** ready-for-agent

### 작성 (Create)
- [ ] 로그인 없이 이름·메시지·비밀번호를 입력하고 제출하면 Entry가 저장된다
- [ ] 제출에 성공하면 폼이 비워지고, 새 Entry가 목록 **맨 위**에 나타난다
- [ ] 서버 검증: 이름은 trim 후 1–20자, 메시지는 trim 후 1–500자, 비밀번호는 trim 없이 4–32자다. 어기면 저장하지 않고 해당 필드 옆에 안내를 띄운다
- [ ] 검증에 실패해도 입력한 이름과 메시지는 폼에 남아 있다
- [ ] 비밀번호 입력칸은 마스킹된다
- [ ] 제출 중에는 버튼이 비활성화되어 중복으로 등록되지 않는다
- [ ] 같은 이름으로 여러 Entry를 남길 수 있고, 각 Entry는 서로 독립적이다

### 조회 (Read)
- [ ] 누구나 페이지에서 전체 Entry 목록을 볼 수 있다(페이지네이션 없음)
- [ ] 목록은 Written at **내림차순**(최신 작성순)으로 정렬된다
- [ ] 각 Entry에 Author name, Message, Written at이 표시된다. Written at은 `Asia/Seoul` 기준 `YYYY-MM-DD HH:mm` 형식이다
- [ ] Message는 일반 텍스트로 렌더링되고(HTML이나 스크립트가 해석되지 않음), 줄바꿈이 유지된다
- [ ] Entry가 없으면 "아직 작성된 글이 없습니다"가 보인다
- [ ] 페이지는 요청마다 최신 데이터를 보여준다. 다른 사람이 쓴 글은 새로고침하면 보인다

### 비밀번호 저장
- [ ] Entry password는 scrypt와 Entry마다 무작위로 만든 salt로 해시해서 저장한다. 평문은 어디에도 저장하지 않는다
- [ ] `listEntries()` 결과와 페이지로 전달되는 데이터 어디에도 비밀번호나 해시가 없다

### 테스트 (Guestbook 모듈 + 인메모리 저장소)
- [ ] 작성에 성공하면 `listEntries()` 맨 앞에 해당 Entry가 있다
- [ ] 여러 개를 쓰면 최신순으로 반환된다
- [ ] 필드별 경계값: 이름 0/1/20/21자, 메시지 0/1/500/501자, 비밀번호 3/4/32/33자, 공백뿐인 이름과 메시지 → `invalid`와 필드별 오류
- [ ] 이름과 메시지의 앞뒤 공백은 저장 전에 제거된다
- [ ] `listEntries()` 결과 객체에 비밀번호 관련 필드가 없다
- [ ] 같은 비밀번호로 쓴 두 Entry의 저장 해시가 서로 다르다

### 연동
- [ ] `entries` 스키마 SQL이 저장소에 있고 Neon에 적용되어 있다
- [ ] 로컬 `next dev`에서 실제 Neon DB로 작성과 조회가 된다
