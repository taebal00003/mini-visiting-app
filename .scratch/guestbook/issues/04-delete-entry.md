# 04: Entry 삭제

**What to build:** 글쓴이는 Entry password를 입력해 자기 Entry를 삭제할 수 있습니다. 비밀번호가 일치하지 않으면 삭제가 거부되고, 그 사실이 해당 Entry에 표시됩니다. 요구사항의 **삭제(Delete)**와 삭제 쪽 **비밀번호 검증**에 해당합니다. 03과 같은 비밀번호 검증 로직을 공유합니다.

**Blocked by:** 02 (Entry 작성과 목록 조회). 03과 동시에 진행할 수 있습니다. 둘 다 Guestbook 모듈을 수정하므로 먼저 들어간 쪽의 비밀번호 검증 코드를 재사용합니다.

**Status:** ready-for-agent

### 삭제 흐름
- [ ] 각 Entry에 [삭제] 버튼이 있다. 누르면 그 Entry 안에 비밀번호 입력 폼이 펼쳐진다. 버튼을 누르는 것만으로는 바로 지워지지 않는다
- [ ] [취소]를 누르면 폼이 닫히고 Entry는 그대로 남는다
- [ ] 제출 중에는 버튼이 비활성화된다

### 비밀번호 검증 (삭제)
- [ ] 비밀번호가 **일치하면** Entry가 DB에서 완전히 삭제되고 목록에서 즉시 사라진다
- [ ] 비밀번호가 **일치하지 않으면** Entry는 **삭제되지 않고**, 그 Entry의 폼 안에 "비밀번호가 일치하지 않습니다"가 보인다
- [ ] 비밀번호 비교는 03과 같은 검증 로직(scrypt + `timingSafeEqual`, 서버에서만 비교)을 쓴다. 검증 코드를 중복으로 만들지 않는다
- [ ] 다른 Entry의 비밀번호로는 이 Entry를 삭제할 수 없다
- [ ] 비밀번호 검증은 Server Action이 아니라 Guestbook 모듈(`deleteEntry`) 안에서 한다

### 오류
- [ ] 이미 삭제된 Entry를 삭제하려 하면 "이미 삭제된 글입니다"가 보이고 목록이 갱신된다. 이 안내는 비밀번호 불일치 안내와 구분된다
- [ ] 예상치 못한 오류가 나면 "잠시 후 다시 시도해 주세요"가 보인다

### 테스트 (Guestbook 모듈 + 인메모리 저장소)
- [ ] 올바른 비밀번호로 삭제하면 `{ ok: true }`가 오고 `listEntries()`에서 사라진다. 다른 Entry는 남는다
- [ ] 틀린 비밀번호로 삭제하면 `wrong-password`가 오고 `listEntries()`에 그대로 남는다
- [ ] 다른 Entry의 비밀번호로 삭제하면 `wrong-password`가 온다
- [ ] 없는 id, 또는 이미 삭제한 id로 삭제하면 `not-found`가 온다
- [ ] `npm test`, `npm run build`, `npm run lint`가 성공하고, 로컬 `next dev`에서 실제 Neon DB로 정상 삭제와 비밀번호 불일치 거부를 모두 직접 확인한다
